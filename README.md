# ระบบบริหารงานทรัพยากรบุคคล โรงพยาบาลหันคา

Progressive Web App (PWA) สำหรับบริหารและวางแผนกำลังคนของโรงพยาบาล รันเป็นเว็บไซต์บน
GitHub Pages และใช้ **Google Sheet เป็นฐานข้อมูล** ผ่าน Google Apps Script

**ทุกหน้าในระบบต้องเข้าสู่ระบบก่อนใช้งาน** และ**ไม่มีฟอร์มกรอกข้อมูลบนเว็บ** — การเพิ่ม/แก้ไข
ข้อมูลบุคลากรทำโดยตรงที่ Google Sheet (แถวและคอลัมน์ตามที่กำหนดไว้) เว็บไซต์ทำหน้าที่อ่านและ
แสดงผลข้อมูลเท่านั้น เหมาะสำหรับให้ฝ่ายบุคคลเป็นผู้ดูแลข้อมูลหลักจุดเดียวใน Sheet

## ฟีเจอร์หลัก

| หน้า | รายละเอียด |
|---|---|
| `index.html` แดชบอร์ด | ภาพรวมกำลังคน: ประเภทการจ้าง, ตำแหน่ง/กลุ่มงาน, Generation, FTE, กลุ่มวิชาชีพ, แนวโน้มเกษียณ, กราฟอายุ, ความเชี่ยวชาญ, ลาออก/เข้าใหม่ |
| `planning.html` วางแผนบุคลากร | หน้ารวมลิงก์ไปยัง 6 โมดูลวางแผนบริหารงานบุคคลด้านล่าง |
| `manpower.html` อัตรากำลัง | กรอบอัตรากำลังมาตรฐานเทียบจำนวนจริงรายตำแหน่ง + ประมาณการบรรจุทดแทนจากแนวโน้มเกษียณ 5 ปี |
| `licenses.html` ใบอนุญาต/ใบประกอบวิชาชีพ | วันหมดอายุใบประกอบวิชาชีพ ชั่วโมง CME สะสม พร้อมแจ้งเตือนใกล้หมดอายุ |
| `succession.html` แผนสืบทอดตำแหน่ง | ตำแหน่งหัวหน้ากลุ่มงาน ผู้ดำรงตำแหน่งปัจจุบัน ผู้สืบทอดที่เสนอ และระดับความพร้อม |
| `development.html` สมรรถนะและแผนพัฒนาบุคลากร | ผลประเมินการปฏิบัติงาน ชั่วโมงอบรม และแผนพัฒนารายบุคคล (IDP) |
| `workforce-risk.html` การลา/ภาระงาน/ความเสี่ยง | สถิติการลา FTE เฉลี่ย และดัชนีความเสี่ยงลาออก (flight risk) รายบุคคล |
| `orgchart.html` ผังโครงสร้างองค์กร | ภาพรวมกลุ่มงาน จำนวนบุคลากร และผู้อาวุโสสุดของแต่ละกลุ่มงาน |
| `login.html` / `register.html` | เข้าสู่ระบบ / สมัครสมาชิกบัญชีผู้ใช้งานระบบ |

ทุกหน้าข้างต้น (ยกเว้น login/register) ต้องเข้าสู่ระบบก่อนจึงจะดูข้อมูลได้ — ถ้ายังไม่ได้เข้าสู่ระบบ
ระบบจะพาไปหน้า `login.html` โดยอัตโนมัติ รองรับติดตั้งเป็นแอป (Add to Home Screen) และเปิดใช้งาน
ได้บางส่วนแบบออฟไลน์ผ่าน Service Worker

## 1) ทดลองใช้งานทันที (โหมดสาธิต)

เปิด `index.html` ระบบจะพาไปหน้า login ก่อน — ล็อกอินด้วยบัญชีทดสอบเพื่อดูข้อมูลจำลอง
บุคลากร ~186 คนที่สร้างและเก็บไว้ใน localStorage ของเบราว์เซอร์โดยอัตโนมัติ

- บัญชีทดสอบ: **admin / admin1234**
- ข้อมูลที่เห็นในโหมดนี้เป็นข้อมูลจำลอง อยู่เฉพาะในเบราว์เซอร์เครื่องนั้น ๆ ไม่ใช่ข้อมูลจริง
- เหมาะสำหรับตรวจสอบหน้าตา/การทำงานของระบบก่อนเชื่อมต่อฐานข้อมูลจริง

## 2) เชื่อมต่อฐานข้อมูลจริงด้วย Google Sheet

### ขั้นตอนที่ 1 — สร้าง Google Sheet และ Apps Script
1. สร้าง Google Sheet ใหม่ (ตั้งชื่อ เช่น `HRHK-Database`)
2. เมนู **ส่วนขยาย (Extensions) > Apps Script**
3. ลบโค้ดเดิมทั้งหมด แล้ววางเนื้อหาจากไฟล์ `apps-script/Code.gs` ที่มากับโปรเจกต์นี้
4. เลือกฟังก์ชัน `setupSheets` แล้วกด **Run** (ครั้งแรกจะต้องอนุญาตสิทธิ์การเข้าถึง Sheet)
   - จะได้ชีต `Staff` และ `Users` พร้อมหัวตาราง และบัญชี admin/admin1234 อัตโนมัติ

### ขั้นตอนที่ 2 — Deploy เป็น Web App
1. มุมขวาบน กด **Deploy > New deployment**
2. เลือกประเภท **Web app**
3. ตั้งค่า:
   - **Execute as:** Me (บัญชีของคุณ)
   - **Who has access:** Anyone
4. กด Deploy แล้วคัดลอก **Web app URL** ที่ได้ (ลงท้ายด้วย `/exec`)

### ขั้นตอนที่ 3 — ตั้งค่าเว็บไซต์ให้เรียกใช้ Apps Script
เปิดไฟล์ `js/config.js` แล้วใส่ URL ที่ได้:

```js
window.APP_CONFIG = {
  GAS_WEB_APP_URL: "https://script.google.com/macros/s/XXXXXXXXXXXX/exec",
  ...
};
```

เมื่อบันทึกและรีเฟรชหน้าเว็บ ระบบจะเปลี่ยนจาก "โหมดสาธิต" เป็นเชื่อมต่อ Google Sheet จริงโดยอัตโนมัติ

### ขั้นตอนที่ 4 — เพิ่ม/แก้ไขข้อมูลบุคลากรที่ Google Sheet โดยตรง
เว็บไซต์นี้**ไม่มีฟอร์มกรอกข้อมูลบนหน้าเว็บ** ฝ่ายบุคคลเพิ่ม/แก้ไขข้อมูลบุคลากรได้โดยเปิดชีต
`Staff` ใน Google Sheet แล้วกรอก/แก้ไขแถวข้อมูลตามหัวตารางที่กำหนดไว้ (ดูรายชื่อคอลัมน์ในหัวข้อ
"การปรับแต่งข้อมูลอ้างอิง" ด้านล่าง) เมื่อบันทึกใน Sheet แล้ว หน้าเว็บทุกหน้าจะอัปเดตข้อมูลอัตโนมัติ
ในการโหลดครั้งถัดไป วิธีนี้ทำให้ Google Sheet เป็นแหล่งข้อมูลจริงเพียงจุดเดียว (single source of truth)
และลดความเสี่ยงข้อมูลไม่ตรงกันระหว่างหลายช่องทางกรอกข้อมูล

> **หมายเหตุความปลอดภัย:** การเข้ารหัสรหัสผ่านใน `Code.gs` เป็นแบบพื้นฐาน (HMAC-SHA256)
> เหมาะสำหรับใช้งานภายในหน่วยงานที่ไม่เปิดสู่สาธารณะวงกว้าง หากต้องการความปลอดภัยระดับสูงขึ้น
> แนะนำให้พิจารณาใช้ Google Identity / OAuth หรือจำกัดสิทธิ์การเข้าถึง Web App เพิ่มเติม
> เนื่องจากทุกหน้าต้องเข้าสู่ระบบ ควรพิจารณาปิดการสมัครสมาชิกแบบเปิดสาธารณะใน `register.html`
> หรือเปลี่ยนเป็นการสร้างบัญชีผ่านฝ่ายบุคคลเท่านั้น หากต้องการควบคุมสิทธิ์การเข้าถึงที่รัดกุมขึ้น

## 3) Deploy เป็นเว็บไซต์บน GitHub Pages

1. สร้าง repository ใหม่บน GitHub เช่น `hr-hankha`
2. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ขึ้น repository (เก็บโครงสร้างโฟลเดอร์เดิมไว้)
3. ไปที่ **Settings > Pages**
4. Source เลือก **Deploy from a branch** → Branch: `main` → Folder: `/ (root)`
5. รอสักครู่ เว็บไซต์จะพร้อมใช้งานที่ `https://<username>.github.io/hr-hankha/`

เนื่องจากไฟล์ทั้งหมดใช้ path แบบสัมพัทธ์ (relative path) จึงรองรับการ deploy ใน sub-path ของ
GitHub Pages ได้โดยไม่ต้องแก้ไขเพิ่มเติม

## การปรับแต่งข้อมูลอ้างอิง

- รายการ **ประเภทการจ้าง**, **ตำแหน่ง**, **กลุ่มงาน**, **สาขาความเชี่ยวชาญ**, **กรอบอัตรากำลัง**
  กำหนดไว้ในไฟล์ `js/mockdata.js` (ตัวแปร `EMP_TYPES`, `POSITIONS`, `DEPARTMENTS`, `SPECIALTIES`,
  `MANPOWER_FRAME`) — ใช้ในโหมดสาธิตและเป็นค่าอ้างอิงของโมดูลอัตรากำลัง ปรับแก้ให้ตรงกับโครงสร้าง
  จริงของโรงพยาบาลได้ทันที
- คอลัมน์ของ Google Sheet ชีต `Staff` กำหนดไว้ใน `apps-script/Code.gs` ตัวแปร `STAFF_HEADERS`
  ประกอบด้วย: `id, firstName, lastName, maskedName, birthDate, age, generation, position,
  department, professionalGroup, employmentType, employmentTypeLabel, fte, specialty, hireDate,
  resignDate, status, phone, licenseNumber, licenseExpiry, cmeHours, performanceScore, idpGoal,
  idpStatus, trainingHours, leaveSick, leavePersonal, leaveVacation, updatedAt` — กรอกข้อมูลใน
  Sheet ตามหัวตารางนี้ให้ครบเพื่อให้ทุกโมดูลแสดงผลถูกต้อง หากต้องการเพิ่มฟิลด์ใหม่ ให้เพิ่มทั้งใน
  หัวตาราง Sheet และ `STAFF_HEADERS` ใน `Code.gs`
- `maskedName` (ชื่อปิดบังบางส่วนที่แสดงในตาราง) คำนวณจาก `firstName`/`lastName` — หากกรอกข้อมูล
  ใน Sheet โดยตรง ควรกรอกคอลัมน์นี้ไว้ด้วย (เช่น "ศรา\*\*\* ม่ว\*\*\*") เพื่อให้หน้าเว็บแสดงผลถูกต้อง

## แนวทางการออกแบบ (Design System)

หน้าตาเว็บอ้างอิง **CorpScale Design System** — ดีไซน์สำหรับงานองค์กร/ระบบ ERP ขนาดใหญ่
โทนสีกรมท่า-เทา-ฟ้า (Navy #1E3A5F, Gray #6B7280, Blue #2563EB) บนพื้นหลังสว่าง #F8FAFC
ใช้ฟอนต์ **Anuphan** ทั้งเว็บไซต์ (หัวข้อและเนื้อหา) ยกเว้นตัวเลขสถิติ/รหัสพนักงานในตารางที่ใช้
JetBrains Mono เพื่อความรู้สึกเชิงข้อมูล มุมโค้งจำกัดไม่เกิน 8px เงาบางเบา ออกแบบเพื่อความหนาแน่น
ของข้อมูล (data density) ชิปสถานะสีความหมาย (เขียว=ปฏิบัติงานอยู่, แดง=ลาออก, เทา=เกษียณ) และมี
breadcrumb + หัวข้อหน้าให้ผู้ใช้รู้ตำแหน่งตัวเองเสมอ
ปรับแก้ธีมสีทั้งหมดได้ที่ตัวแปร CSS custom properties ในไฟล์ `css/style.css` (ส่วน `:root`)

## เทคโนโลยีที่ใช้

- HTML / CSS / Vanilla JavaScript (ไม่ต้อง build)
- [Chart.js](https://www.chartjs.org/) สำหรับกราฟในแดชบอร์ด (โหลดผ่าน CDN)
- Google Apps Script + Google Sheets สำหรับฐานข้อมูลและ API
- Web App Manifest + Service Worker สำหรับความสามารถ PWA
